# ЗДРАВА | Аналитика — Telegram Bot v0.2

Самостоятельный Telegram-бот статистики двух лендингов: [Микозацид](https://zdrava.top/mikozacid/) и [Горячий лёд](https://zdrava.top/hot-ice/). Ориентирован на Bothost, Python 3.11, Dockerfile и Telegram long polling. **Без SQL/БД:** данные сохраняются в JSON в `/app/data`.

Код можно держать в **публичном GitHub-репозитории**, потому что реальные токены, приватные ключи, пароли и ID пользователей должны находиться **только в переменных окружения Bothost**. `.env`, `data/`, ключи и временные файлы исключены через `.gitignore` и `.dockerignore`. Не храните секреты в репозитории и не отправляйте их в чат.

## Возможности v0.2

- `/start` — меню; все отчёты доступны только Telegram ID из allowlist.
- `/today`, `/yesterday`, `/week`, `/month` — визиты и посетители по двум страницам Яндекс.Метрики; 7 и 30 дней — завершённые дни.
- `/sources`, `/utm` — источники и UTM-кампании за последние 7 завершённых дней.
- `/status` — состояние конфигурации; `/check` — реальная проверка API Метрики, Google (если включён) и записи в `/app/data`.
- `/search` — данные Google Search Console (при подключении), за 7 завершённых дней.
- `/spend mikozacid 2026-11-09 500` — ручной учёт расходов по товару на дату (заменяет ранее введённую сумму).
- Ежедневная сводка в Telegram за вчера, по умолчанию в 09:00 Europe/Moscow; запоминает доставку в JSON.
- `/id` — показывает ваш Telegram ID (доступно до настройки allowlist).

**Ограничения.** Обычная Метрика не знает, кто купил товар на Ozon. Опционально отображаются **достижения цели перехода в Ozon** (это не продажи), если настроена цель и указан её ID. Атрибуция заказов и внешних расходов Ozon, автоматическая загрузка рекламных расходов отсутствуют. Wildberries не подключён.

## Bothost: порядок развёртывания

1. Создайте **нового Telegram-бота** через [@BotFather](https://t.me/BotFather), команда `/newbot`. Сохраните выданный токен — **не публикуйте** его.
2. Узнайте свой **числовой** Telegram ID (через @userinfobot или другого проверенного бота). Без `TELEGRAM_OWNER_IDS` новый процесс не запустится — так защищены отчёты.
3. На [Bothost](https://bothost.ru/) создайте отдельное приложение Telegram/Python и выберите Git-репозиторий `https://github.com/HRAKEH/zdrava-analytics-bot`, ветку `main`.
4. Включите использование **собственного Dockerfile** из корня репозитория. В нём уже указана команда запуска `python main.py`. **Webhook, домен и открытый порт не требуются**, поскольку используется polling. Не запускайте вторую копию с тем же токеном.
5. В разделе **Переменные окружения** Bothost добавьте обязательные переменные ниже. Не создавайте `.env` в GitHub.
6. Запустите деплой, затем зайдите в нового бота: `/start` → `/check` → `/yesterday` → `/utm`. При ошибках проверьте логи Bothost.
7. `/app/data/` используется ботом автоматически. Для платного тарифа убедитесь, что постоянное хранилище включено; при обновлении Git данные должны сохраняться. Копии JSON рекомендуется периодически сохранять отдельно.

### Обязательные переменные окружения

| Ключ | Значение/откуда взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен **нового** бота от BotFather. Если Bothost автоматически устанавливает `BOT_TOKEN`, можно использовать его вместо этой переменной. |
| `TELEGRAM_OWNER_IDS` | Ваш числовой Telegram ID; для нескольких владельцев через запятую, например `111111111,222222222` (**пример, не ваши ID**). |
| `METRIKA_TOKEN` | OAuth-токен Яндекса с разрешением **читать статистику** счётчика. Получите в настройках своего OAuth-приложения, от имени пользователя, которому доступен счётчик. |
| `METRIKA_COUNTER_ID` | `113941063` — идентификатор счётчика ЗДРАВА из проекта; проверьте, что токен имеет к нему доступ. |

Бот запустится и без `METRIKA_TOKEN`, но отчёты Метрики и ежедневная сводка будут недоступны до подключения.

### Необязательные переменные

| Ключ | Значение по умолчанию / назначение |
|---|---|
| `DATA_DIR` | `/app/data` — JSON-кэш, расходы, статус отправки. |
| `TIMEZONE` | `Europe/Moscow` — локальное время отчётов и команды `/today`. |
| `DAILY_REPORT_ENABLED` | `true` — отправлять ежедневную сводку. |
| `DAILY_REPORT_TIME` | `09:00` — HH:MM по `TIMEZONE`. |
| `METRIKA_OZON_GOAL_ID` | ID **существующей** цели перехода на Ozon в Метрике. Если не знаете или цели нет — **не заполняйте**. Не путать с номером счётчика. |
| `HTTP_TIMEOUT_SECONDS` | `20` — таймаут HTTP запросов, 5–120 сек. |
| `GSC_PROPERTY` | `sc-domain:zdrava.top` для доменного ресурса; для URL-prefix укажите **точный** адрес из Search Console, например `https://zdrava.top/`. |
| `GSC_SERVICE_ACCOUNT_B64` | Base64-кодированное **полное JSON-содержимое** ключа Google service account. Храните **только в Bothost**. Если не подключаете GSC, не задавайте. |
| `GSC_SERVICE_ACCOUNT_FILE` | Альтернатива B64: путь к ключу, по умолчанию `/app/data/gsc-service-account.json`. B64 имеет приоритет. |

#### Как подключить Google Search Console **без файла на хосте**

1. В Google Cloud включите **Search Console API** и создайте **service account** с JSON-ключом.
2. Добавьте email этого service account в настройки доступа нужного ресурса Search Console. Проверьте, что значение `GSC_PROPERTY` в точности соответствует этому ресурсу.
3. **На своём ПК** превратите JSON в Base64 одной строкой (не отправляйте ключ в чат):

   Windows PowerShell:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\\path\\service-account.json"))
   ```
   Linux/macOS:
   ```bash
   base64 < service-account.json | tr -d '\\n'
   ```
4. Вставьте полученную строку только в значение `GSC_SERVICE_ACCOUNT_B64` в Bothost. Не добавляйте её в `.env.example`, GitHub или README. Выполните деплой и запустите `/check` и `/search`.

**Важно:** сервисный аккаунт нужен только для GSC; токены Яндекс.Метрики и Telegram настраиваются отдельными переменными. Base64 **не шифрует** секрет; это лишь формат передачи через переменную окружения.

## Проверки и устранение проблем

- `/check`: есть ли доступ к Метрике и GSC (при подключении), работает ли `/app/data`.
- HTTP 401/403 Метрики — проверить токен, разрешения OAuth и доступ к счётчику `113941063`.
- Google 403 — сервисный аккаунт должен иметь доступ к **нужному ресурсу** Search Console; `GSC_PROPERTY` должен соответствовать ему.
- `409 Conflict` Telegram — один и тот же токен одновременно используют две запущенные копии; остановите лишнюю.
- В боте нет визитов — проверить корректность счётчика и путь лендинга, наличие данных в Метрике, а также что отчёт за сегодня может быть неполным.
- Отчёт за сегодня неполный; Google также публикует поисковую статистику с задержкой.
- Если API не подключён — числа не подставляются и не выдумываются.

## Локальный запуск и тесты

```bash
python -m venv .venv
# Активируйте окружение; Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env       # Windows: copy .env.example .env
# Заполните .env реальными ключами ТОЛЬКО на своём ПК; DATA_DIR=./data
python main.py
```

Тесты (с замокированными ответами, не затрагивают API):

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```
